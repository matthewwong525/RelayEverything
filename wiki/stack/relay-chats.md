# Relay Everything's AI chat transcripts

Relay Everything saves Claude Code and Codex chats through its copy in each project, made from [`plugin/`](../../plugin/README.md): each chat goes to the Relay Everything server as you talk, shows under **Connect your AI**, **Saved chats**, on the Relay Everything page, and the [AI connector](relay-ai-connector.md) searches it. The same copy lets the AI in the chat read the person's data and add notes, through the web API. It is part of [the Cloudflare stack](README.md). The website's [Save AI chat transcripts](../../site/src/content/docs/connections/claude-code.md) page owns the person's steps; this page owns how it works and how to change it.

## How a computer connects

1. `/relay-connect` runs `bin/connect.mjs start`: it makes a secret, sends its SHA-256 and the computer's name to `POST sign-in/computer/start`, and shows the link and a code such as `KITE-4821`. A detached waiter asks `POST sign-in/computer/key` every 3 seconds for 10 minutes.
2. The person opens the link, signs in, checks the code and clicks **Connect** ([`sign-in/computer.ts`](../../app/worker/apps/relay/sign-in/computer.ts)). The row in `relay_computer_codes` then names them.
3. The next ask, with the secret, gets the key once: a device row with `reaches = 'agent'`, made by `makeDevice`. The copy keeps it in the computer's own key file, mode `0600`, under `RELAY_EVERYTHING_HOME` when set.

The start and the ask need no person: the secret protects them, so they pass a self-hosted server's Access wall (`NO_PERSON` in [`relay-only.ts`](../../app/worker/relay-only.ts)) and the Origin check. The ask has no rate limit: the secret is 256 bits and lives 10 minutes, and a limit of 10 a minute would refuse the waiter. **Add an API key** makes only an `api` key: never an `agent`, `chats` or phone key.

## How a chat travels

1. The computer's key goes as `Authorization: Bearer`. On the server it reaches only `POST chats`, `POST chat-saves` and `GET key`; [`caller.ts`](../../app/worker/apps/relay/caller.ts) checks the method and path. It reads through the connector's `/v1/`, as an API key does. An older chat key (`reaches = 'chats'`, from plugin 0.2) still sends, and `/v1/` refuses it with a line that says to run `/relay-connect`. A phone key can't reach a chat route.
2. The copy's hooks run `.agents/relay/bin/hook.mjs` in both apps: `SessionStart` notes the session and sends any send that failed before, `Stop` sends the new messages, and `SessionEnd` starts a detached send so the app's short end budget never cuts it. A session's project is its git top folder, and a worktree counts as its main repository (read from the `.git` file's `gitdir` and `commondir`, with no `git` call), so saving off and the project's name hold in each workspace copy.
3. [`lib/transcript.mjs`](../../plugin/lib/transcript.mjs) reads a Claude Code transcript and [`lib/codex.mjs`](../../plugin/lib/codex.mjs) a Codex rollout: what you typed, the AI's text, and one line per tool step. Tool output, thinking, helper chats and unknown lines are never sent. [`lib/hide.mjs`](../../plugin/lib/hide.mjs) replaces key shapes and `.env` values with `[hidden]` first.
4. [`chats.ts`](../../app/worker/apps/relay/chats.ts) stores messages once each by `(chat, seq)` and answers only `stored`. A gap answers 400 with `stored`, and the copy sends again from there, as after a delete. `app` is `claude-code` or `codex`; the first send keeps it, and none means `claude-code`.
5. A person reads and deletes through [`chat-read.ts`](../../app/worker/apps/relay/chat-read.ts); every device key is refused there. The connector's `search_chats` and `read_chat` and `/v1/chats` read through [`queries.ts`](../../app/worker/apps/relay/queries.ts), each with the chat's `app`.

`POST chats` is a bare route, not a contract action: the contract turns a 413 into a 400 and drops `stored` from an error. Its fields are on the website page, through `HAND_PAGES` in [`api-doc.ts`](../../app/worker/apps/relay/api-doc.ts).

## How the AI reads

The `relay-ask` skill runs `bin/relay.mjs`, which maps each command to one `/v1/` route with the computer's key. Two commands join reads into one answer, and a part that fails goes under `errors` by name: `around` reads a note, then its day, notes, places, calendar and hourly steps and heart rate in a window of 2 to 12 hours each way; `topic` reads a page and its links from the copy of the knowledge web, then the topic's facts, notes and up to 3 chats its facts name. A refused key stops the whole answer.

[`lib/topics.mjs`](../../plugin/lib/topics.mjs) reads the copy as plain files. At `SessionStart` the hook prints the top-level topics, at most 40, and starts `knowledge.mjs sync` detached; at `UserPromptSubmit` it adds at most 3 topics the message names. Both only read the copy, so they run with saving off or `RELAY_SAVE=0`, but not on a computer that is not connected. The first `SessionStart` of the day also starts the daily build: [how the web is built](relay-knowledge-web.md#how-the-web-is-built).

## The copy in a project

`plugin/` is the one source of both the copy and the last plugin. [`install.mjs`](../../plugin/install.mjs) `--into <project>` copies it into `<project>/.agents/relay/`, less `.claude-plugin/`, `test/`, `skills/move/` and `VERSION`, and writes `RELEASE`: the version and the commit, or the tag, it came from. It links each skill as `.claude/skills/relay-<name>` and, for Codex, `.agents/skills/relay-<name>`; one link serves both when `.claude` is `.agents`. It merges `hooks/claude.json` into `.claude/settings.json` and `hooks/codex.json` into `.codex/hooks.json`, adding only the groups that are missing. A project with `RELEASE` changes nothing. The website's [Install](../../site/src/content/docs/install.md) page owns the person's steps.

- **Paths.** A skill runs `node "$(git rev-parse --show-toplevel)/.agents/relay/bin/<script>.mjs"`. A Claude Code hook runs from `$CLAUDE_PROJECT_DIR`, a Codex hook from `$(git rev-parse --show-toplevel)`. Each script finds its own folder from `import.meta.url`, so nothing reads `CLAUDE_PLUGIN_ROOT`.
- **Per computer, not per project.** The key, `state/`, `knowledge/`, `build.json` and `build/` stay in `~/.config/relay-everything/`, so one sign-in serves every project with the copy. Two copies on different releases share these files, so a state file only gains fields.
- **[`update.mjs`](../../plugin/update.mjs)** merges the newest `relay-v*` release into the copy three ways, with the release in `RELEASE` as the base: `check`, `plan` (writes nothing), `show <path>` for a clash, and `apply --choose <path>=mine|release|both`. A file both sides changed merges with `git merge-file`; lines both changed are a clash, which `apply` refuses until each one has a choice. `apply` then rewrites `RELEASE`, links a new skill, unlinks a gone one, and swaps the old release's hook groups for the new ones. `--releases <folder>` reads `<folder>/<version>/` in place of GitHub.
- **The last plugin, 0.7.0.** Claude Code and Codex give a plugin's hook `CLAUDE_PLUGIN_ROOT` or `PLUGIN_ROOT`, and a project's hook neither. From the plugin, `hook.mjs` does nothing in a project with `.agents/relay/RELEASE`, so no chat is sent twice, and says once on each computer that Relay Everything moved. Its `/relay:move` skill runs the plugin's own `install.mjs`, and on the person's yes removes the plugin.

## Change the copy

- **No packages.** The copy is plain Node 20 or later, with no `npm install`: only `plugin/` goes to a project, so it can't import anything else in the repository.
- **One source, two apps.** Claude Code and Codex read the same skills and `hook.mjs`. Codex skips an `"async": true` hook and keeps `SessionEnd` to 3 seconds, so no hook is async: the send runs detached before memory's end, which gets 5 seconds in Claude Code and may be cut in Codex. `plugin/test/hooks.test.mjs` fails when `claude.json`, `codex.json` and the plugin's `hooks.json` name different events, scripts or time limits.
- **Codex runs only trusted hooks.** Codex asks the person to trust the project's hooks (**Trust all and continue**, or `/hooks`), and again after an update that changes a hook. With no trust it runs none and says nothing, so no chat saves. `codex exec` runs an untrusted hook only with `--dangerously-bypass-hook-trust`.
- **What Codex gives a hook and a skill.** A hook gets on stdin `session_id`, `transcript_path` (the rollout under `~/.codex/sessions/`) and `cwd`. A skill gets no `$ARGUMENTS`, so each skill says to put the person's words in its place; the session id is `CODEX_THREAD_ID`. Codex types a skill as `$relay-connect`, not `/relay-connect`.
- **The key shapes are copied.** `lib/hide.mjs` copies the shapes of the memory store's [`scan.mjs`](../../.agents/skills/memory/scripts/lib/scan.mjs) by name. `plugin/test/hide.test.mjs` fails when `scan.mjs` gains a shape the copy lacks.
- **No key in `plugin/`, and one address.** The only address is the default server, `https://app.relayeverything.com`; the key file names the server after `/relay-connect`. `plugin/test/no-secrets.test.mjs` fails on a key shape, any other address or an email in the folder.
- **Test it:** `node --test plugin/test/*.test.mjs`, which `npm test` in `app/` also runs, and `claude plugin validate plugin`.
- **Memory is a copy.** `plugin/memory/` is a copy of [memory's plugin folder](../../.agents/skills/memory/SKILL.md), less WongStack's hooks, manifests, daily tidy, setup guide, document-search packages and store contract; `plugin/skills/memory/SKILL.md` is its skill with the copy's command. Never edit it: `node scripts/copy-plugin-memory.mjs` makes it again. `plugin/test/memory-copy.test.mjs` fails while it differs, so a `/wong-sync` that changes memory runs the script in the same change. `plugin/memory-profile.mjs` is Relay Everything's profile, and `hook.mjs` runs memory's hook scripts only with memory on and no memory of the project's own.
- **Ship a new release:** run `node scripts/copy-plugin-memory.mjs`, then raise `plugin/VERSION`. After the change merges, tag `main` with `relay-v<version>` and push the tag: `/relay-update` and the install page read only these tags, so a release with no tag reaches no project. While the plugin is still listed, raise `version` in `plugin/.claude-plugin/plugin.json` too: each app updates an installed plugin only when it changes.

## Try it on staging

Never install Relay Everything in your own setup to try it. Give each app a scratch home, so nothing touches `~/.claude` or `~/.codex`:

1. Make `.scratch/claude`, `.scratch/codex` and `.scratch/relay`. Copy `~/.claude/.credentials.json` into `.scratch/claude` and `~/.codex/auth.json` into `.scratch/codex`, so each app can sign in. Delete the folders when you finish.
2. Start each app with `CLAUDE_CONFIG_DIR`, `CODEX_HOME` and `RELAY_EVERYTHING_HOME` on those folders, in a new git project under `.scratch/`. Install from this branch: `node plugin/install.mjs --into <the project>`. To try the plugin's move, add the plugin instead: `claude plugin marketplace add <this checkout's path>` and `claude plugin install relay@relay`, or `codex plugin marketplace add <path>` and `codex plugin add relay@relay`.
3. In Codex, pick **Trust all and continue** for the hooks. Type `/relay-connect https://app-staging.relayeverything.com` (`$relay-connect …` in Codex), open the link signed in to staging, and click **Connect**. With no browser, add a test person and a session to the staging database, as [person spaces](../relay-spaces.md) says, and send the form with `curl`: `c`, `name`, `choice=connect`, the `__Host-relay_session` cookie and `Origin: https://app-staging.relayeverything.com`.
4. Have a short chat, ask *save this*, and ask about a seeded note. Open **Connect your AI**, then **Saved chats**, on staging to see the chat with its app.
5. To try an update, copy `plugin/` twice into a folder as `<folder>/<version>/`, raise `VERSION` in the second and change a file, edit the project's copy, and run `node .agents/relay/update.mjs plan --releases <folder>`.
6. Delete the chat, then click **Turn off** beside the computer in **Devices**. For a test person, `POST account-delete` with its email deletes the person, the chats and the key.

Run `codex exec` with stdin closed (`</dev/null`) and a time limit: it can wait for input forever. `codex exec` can't ask you to approve a command outside the sandbox, so it can't try a skill as a person uses it. Start the Codex screen in `tmux new-session -d`, type with `tmux send-keys`, read it with `tmux capture-pane -p`, and press `y` at each *Would you like to run the following command?*.
